# ADR-0007：以业务分类扩展发货，复用履约流程

状态：接受

日期：2026-09-06

## 背景

门店补发、换货和合作样品需要清晰归属和用途，但收件、明细、面单与物流流程相同。若为每类复制发货表与队列，权限和取消保护容易产生分叉。

## 决策

- 在现有发货模型增加固定业务分类，以 `stores.kind` 区分实体门店和团队；账号继续按 `store_id` 隔离。
- 保留独立的原发货、客户退货、新寄出记录；只通过同归属外键关联，不覆盖原单，未签收退货只提醒。
- 历史记录默认 `legacy`，不根据备注自动分类；新的普通单明确写入 `standard`。
- 内部原因和合作项目与可打印包装要求分开；临时物料仅保存于发货明细快照。
- 特殊单使用自动编号以及数据库事务内幂等键；不增加审批、退款或库存扣减。
- 所有列表/汇总/导出/打单范围复用一个服务端分类过滤器；统计仅增加固定类别数量，既有口径兼容。

## 约束与影响

增量 Schema 不改旧记录业务内容；账号通过总部正常创建，不植入默认合作密码。新增类别后旧代码不能安全编辑特殊单，回滚必须遵守 [功能文档](../features/special-shipments.md) 的兼容限制。

若未来出现跨归属协作、审批或库存结算需求，另评估相应权限和状态机，不用改备注或伪造门店解决。

# ADR-0006：时间字段使用证据等级与受控历史修复

- 状态：已接受，代码未部署
- 日期：2026-08-29

## 背景

2026-08-28 的只读日报仍有 8 项发货/签收时间质量计数；对部署前受控备份的脱敏聚合显示相同结果，指向 6 条早期历史记录而非持续新增。现有物流写入可推进状态却不总是补齐 `shipped_at`，而人工、面单和兼容迁移虽可能补当前时间，却无法表达这是业务精确时间还是估算值。2026-08-17 的 `legacy_snapshot` 只能证明迁移时状态，不能反推历史发生时间。

## 决策

- 在数据库写入层统一校验时间可解析、发货不早于创建、签收不早于发货，并用 SQLite 触发器保护绕过普通方法的新写入。
- 时间值同时保存 `exact`、`estimated` 或 `legacy_unclassified` 证据等级及固定来源；系统观察到标签/查询的精确时刻不等同于实际业务发货时刻。
- 历史工具默认 dry-run、聚合输出。精确与估算候选分开统计，证据冲突保持未修复；估算写入需要额外显式授权。
- apply 必须同时具备数据库绝对路径复核、预览指纹、影响上限、固定确认短语和通过完整性检查的在线备份。业务更新与只追加审计位于同一事务。
- 日报继续报告原始质量问题，并新增精确、估算、仍缺证据三组当前快照；不得通过排除估算或旧值让问题表面消失。

## 影响

- Schema 向后兼容增加四列、一个无个人字段的只追加修复事件表、索引和完整性触发器；旧代码可忽略新增列和表。
- 部署初始化只分类已有合法时间为 `legacy_unclassified`，不修复 6 条已知历史记录；生产修复必须另开授权任务。
- 代码回滚可保留新增列、表和事件。数据回滚依赖 apply 前已校验备份，不删除修复事件来伪造回滚。

## 被否决方案

- 用 `legacy_snapshot.occurred_at` 填历史时间：它是迁移时间，不是业务证据。
- 对全部异常批量写 `updated_at`：会把估算伪装为精确，且无法处理冲突。
- 日报隐藏已估算或旧记录：会破坏质量趋势的真实性。

# ADR-0004：日报使用独立令牌与只读连接

- 状态：提议（已开发、未部署/待验收）
- 日期：2026-08-05

## 背景

每日盘点需要稳定读取业务汇总，但现有总部会话权限同时覆盖诊断、设置、备份和业务写操作。把总部 Cookie 或普通数据库连接交给自动任务会扩大凭据权限，也可能触发初始化或迁移路径。生产数据库还包含个人信息和原始供应商报文，报表不能依靠调用方自行脱敏。

## 决策

- 日报使用只属于一个精确 `GET` 路径的独立 Bearer 令牌，不创建用户、会话或新角色。
- 令牌只从 `SCENTPOOL_AUDIT_TOKEN` 读取，经固定长度摘要和恒定时间比较验证；认证失败不区分缺失、错误或未配置。
- 日报令牌不能通过普通管理员鉴权，普通管理员会话也不能通过日报鉴权。
- 数据库访问使用新建的 SQLite URI `mode=ro` 连接和 `PRAGMA query_only=ON`，不复用写连接或初始化逻辑。
- 响应采用显式字段白名单，只返回汇总数字、门店名和固定口径元数据。
- 没有事件日志支持的历史积压和历史失败只作为当前快照返回并明确命名；不计算伪精确的历史均值。

## 影响

- 部署需要新增一个受控环境变量，但不需要 Schema 迁移或业务数据写入。
- 自动任务获得的权限小于总部会话；泄漏后的影响面仍需通过令牌轮换控制。
- 报表每次请求建立短生命周期只读连接，读到 SQLite/WAL 的一致快照，不承担多实例报表副本能力。
- 若数据库不可读，接口返回通用错误，不回退到普通写连接。
- 精确历史积压或失败趋势需要未来增加只追加事件模型和专项迁移，不能从当前覆盖式字段倒推。

## 重新评估触发条件

- 每日盘点需要精确状态历史、失败发生次数或历史积压均值。
- 报表查询对在线 SQLite 产生经测量的明显负载，需要独立副本或数据库迁移。
- 需要多类审计调用方、不同字段权限或标准短期凭据，此时应评估更完整的服务身份机制，而不是共享同一 Bearer。

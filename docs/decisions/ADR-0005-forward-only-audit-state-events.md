# ADR-0005：用脱敏只追加事件提供前向完整日报历史

- 状态：已接受，待部署
- 日期：2026-08-15

## 背景

发货单、面单、物流和打印当前字段采用覆盖式状态。`created_at`、`shipped_at` 与 `tracking_signed_at` 能解释部分事件，但取消可能清空发货时间，失败恢复会覆盖失败状态，打印也没有独立失败/恢复时间。因此现有数据库不能准确复原任意历史日的日末积压和“当日发生后已恢复”的失败；把当前快照倒推成历史会产生伪精确结果。

日报仍必须保持独立 Bearer、GET-only、SQLite `mode=ro` + `query_only` 和最小脱敏响应，不能为报表复制个人发货字段或供应商原始报文。

## 决策

- 增加 `audit_event_meta`，记录事件证据启用时间、首个完整上海自然日和 Schema 版本。
- 增加 `audit_state_events`，按发货状态、面单、物流和打印保存规范化状态变化。事件只含领域、实体类型、内部整数记录号、事件类型、固定状态/原因分类、记录创建时间、发生时间和证据来源。
- 数据库首次迁移时为现有记录写入一份 `legacy_snapshot`；此后由 SQLite 触发器自动追加 `observed` 事件。事件表没有姓名、电话、地址、业务编号、门店订单号、快递单号、密钥、错误原文或第三方原始报文。
- 用数据库触发器拒绝事件 UPDATE 和 DELETE。业务记录删除只追加 `deleted` 状态，不级联删除历史证据。
- 只有请求日期不早于 `full_day_coverage_from`，且该上海自然日已结束时，日报才把日末状态和当日失败标为完整；更早或尚未结束的日期继续使用可验证的当前字段观察值，并返回 `partial` 与固定限制代码。
- 失败原文在写入事件前映射为供应商/API 拒绝、系统异常/超时、数据或配置问题、历史证据不足四类；日报只返回分类、计数和固定非技术处理提示。
- 保留原 `metrics.backlog_current_snapshot` 与 `exceptions` 字段及其限制，避免静默改变旧调用方语义；新增历史调用方使用 `historical_end_of_day`、`failures` 和 `completeness`。

## 影响

- 这是向后兼容的增量 Schema。首次部署会写入一份脱敏状态快照并创建索引/触发器，不批量修改业务状态或个人字段。
- 每张新发货单初始追加四条小型状态事件，后续只在状态变化时追加；按当前每天 80–200 单的量级远低于 SQLite 迁移阈值，但诊断会统计事件表大小，后续应观察增长。
- 日报的窗口查询使用领域/时间及实体/时间索引，并在短生命周期只读连接的一致快照中执行。若实测出现明显慢查询，应先测量与优化索引，不改变 GET-only 或只读边界。
- 部署前需要 SQLite 在线备份和完整性检查。代码回滚可保留新增表与触发器；旧代码忽略它们，继续保留状态证据，无需破坏性删表。
- 迁移前的失败恢复和状态变化永远无法从现有覆盖字段补回；`full_day_coverage_from` 不得人为提前。

## 重新评估触发条件

- 审计事件增长显著影响在线写入或日报查询延迟。
- 需要保存更多领域、跨服务共享事件，或需要不可抵赖的外部审计存储。
- SQLite 达到 `OPERATIONS.md` 的迁移阈值，届时事件表应随业务数据一起进行完整性迁移与计数核对。

# ADR-0011：独立库存集成权限与可校验状态流

- 日期：2026-10-14
- 状态：接受于开发分支；生产发布尚未授权。

## 背景

进销存需要同步发货事实并委托补货/渠道发货，不能获取普通订单的个人信息，
不能将顾客代发与库存内部流转混为一类，也不能因网络重放重复扣库存或取号。

## 决策

1. `/api/inventory/v1` 采用独立 Bearer，不复用审计令牌、员工或总部会话。
   权限仅覆盖脱敏目录/事件、集成自有任务、商品主档和自有有效 PDF。
   PDF 本身可能含收件信息，消费端须按自身操作员权限代理，禁止公开链接及正文日志。
2. 在旧履约表复用队列和成功批次快照，新增不可变来源与外部 UUID。内部归属是
   停用的系统团队/员工，不是可登录的总部账号；实际业务归属保存在内部元数据。
   普通列表、普通商品报表及异常中心排除库存任务；总部可按 ID 核对并用原流程取消。
   日报全平台总量保留，库存任务单独分类，不伪装成销售。
3. 创建与 book 键分别全局幂等，事务提交与队列同生共死。明确失败可人工用同 key
   重排原批次，保留原请求/原配置；GET 不重试。取消确认后新发货必须新 key。
   不新增库存端取消 API；无法确认取消的任务不清空，不自动换 key。
4. Worker 写结果须匹配当前批次、原请求和领取时的尝试计数。取消结果保存须匹配
   发送取消时的请求身份。旧取号、旧取消和旧打印回调不能改变后来的有效发货。
5. SQL 触发器在原事务中追加轻量变更通知，持久游标可有间隙；最新指针合并到每单
   当前已提交状态，包含删除墓碑。它不是逐笔库存流水，也不承诺逐个重放中间状态。
   消费方以自身已存状态计算差值，并在同一事务中保存状态和续读位置。
6. 初始历史仅参考，所有迁移前记录永久保留 historical_reference；不能补扣。
   首次消费须建立自己的基线。渠道仅取当前请求对应的成功快照，未知不能猜。
7. 游标增加持久 stream UUID 与每条事件的随机 checkpoint。后续正游标必须携带
   stream/checkpoint。恢复至旧备份后即使序号重新增长也能识别不同分支，返回409，
   必须人工对账，禁止自动从0重新扣减。合法共同前缀仍可继续。
8. 新迁移以保存点保证新增列/表/触发器/历史基线整体回滚。事件只追加，不自动裁剪；
   目录、分页、响应大小、并发和查询时间有硬上限，超限明确失败不截断。

## 发布与重新评估

正式发布需在线备份完整性通过、确认双端契约、独立生成生产令牌和新中台切换窗口。
备份不能恢复到已经有新业务写入的数据库。回退先关闭集成并核对活动任务；
旧二进制不理解来源隔离，不能直接回退让普通后台误处理库存单。
事件表增长需要监控；引入保留/裁剪策略前必须设计消费确认点和重新建基线程序。

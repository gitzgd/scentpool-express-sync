# ADR-0001：单实例阶段继续使用 SQLite

- 状态：接受
- 日期：2026-07-19；2026-08-03 文档化

## 背景

系统生产部署为单个 Render Web Service 和一个持久磁盘。历史内存事故的主要原因是批量 PDF 处理和线程内存分配，不是 SQLite 数据量或查询性能。

## 决策

在单实例、当前订单规模和现有恢复要求下继续使用 SQLite WAL。保留在线备份、完整性检查、固定请求线程池、锁等待和低内存配置。

不因为文件增长本身立即迁移 PostgreSQL。

## 影响

- 数据库必须位于持久磁盘。
- 服务仍以单实例写入为主。
- Schema 迁移必须兼容已有生产数据库并覆盖旧库测试。
- 备份、恢复演练和磁盘监控是继续使用 SQLite 的必要条件。

## 重新评估触发条件

出现下列任一情况时启动专项迁移评估：

- 数据库或磁盘达到 `OPERATIONS.md` 的验证门槛。
- 持续出现数据库锁冲突。
- Web 服务需要两个或更多实例。
- 需要高可用、分钟级恢复点、跨服务共享数据库或独立报表副本。

触发条件的具体数值需随生产证据更新，不能永久依赖事故期估算。

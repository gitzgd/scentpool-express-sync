# ADR-0002：只有供应商确认后才释放电子面单

- 状态：接受
- 日期：2026-07-15；2026-08-03 文档化

## 背景

电子面单可能已经在快递公司或菜鸟侧生效。本地清空单号并不代表供应商已经回收面单。如果在取消失败后重新下单，可能同时产生两个有效单号。

普通圆通当前供应商通道还可能不支持接口取消。

## 决策

- 下单时保存取消所需的原授权参数快照。
- 取消请求复用原下单参数。
- 只有供应商明确返回成功，系统才清空旧单号并恢复待处理状态。
- 供应商拒绝或响应不确定时保留旧单号、面单地址和锁定状态。
- 确认取消后的重新下单生成新的请求 ID。
- 对同一进行中请求保留幂等重试能力。

## 影响

- 前端提示不能把本地操作描述成供应商已经成功取消。
- 数据库迁移必须保留历史订单取消所需的授权快照。
- 自动化测试需要覆盖成功、拒绝、重复请求和取消后重新下单。
- 不支持接口取消的承运商需要人工回收流程。

## 重新评估触发条件

当快递100或承运商提供新的正式取消能力，或系统切换取号主体时，重新验证参数、幂等规则和“谁取号谁取消”的限制。

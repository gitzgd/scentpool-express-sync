# ADR-0003：普通改动默认发布并提供本地验收界面

- 状态：接受
- 日期：2026-08-03

## 背景

用户希望只描述功能目标，不再逐次决定是否暂存、提交、推送和部署；用户可见改动发布后，还需要一个与生产数据隔离的本地测试界面，通过少量典型案例直观看到效果。

## 决策

- 边界清楚的普通功能、修复和界面调整，在验证通过后默认由统一工作台自行暂存、提交、推送、创建并合并 PR，并部署到已核实的生产服务，不再重复询问是否提交或推送。
- 发布前必须确认分支、差异、测试结果、精确生产服务和回滚路径；不得把待补验证描述成已经通过。
- 用户明确要求“仅本地”“暂不发布”或“只做检查”时，不执行合并或生产部署。
- 用户可见行为部署完成后，默认启动只含 2 至 3 个合成案例的本地验收界面；不得复制生产订单、顾客信息、会话或数据库到测试环境。
- 对抗性审查覆盖错误输入、外部服务失败、历史兼容、权限边界和可读失败提示。

## 仍需单独确认的操作

以下高风险动作不包含在默认发布授权中：生产数据库恢复或直接修改、生产密钥和环境变量修改、删除服务或磁盘、清理真实订单、不可逆迁移，以及精确目标无法核实时的外部操作。

## 影响

- 普通改动的交付路径更短，但发布状态、验证缺口和生产结果必须记录在 `docs/STATUS.md`。
- 本地验收界面是发布后的独立合成环境，不代表再次部署，也不能作为生产健康检查的替代品。
- 如果自动部署失败，应停止在失败点，保留可回滚状态并向用户报告明确原因。

## 重新评估触发条件

当部署平台、生产服务、默认分支、数据迁移风险或用户发布偏好改变时，重新评估本决策。

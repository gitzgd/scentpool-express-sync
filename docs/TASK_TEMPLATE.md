# 独立任务模板

复制下面的模板创建功能、修复、体验、文档或运维任务。

```text
任务名称：<类型>｜<清晰目标>
项目目录：/Users/zgd/scentpool-express-sync
环境：Worktree
起点：最新 main

开始前读取：
- AGENTS.md
- docs/PROJECT_CONTEXT.md
- docs/ARCHITECTURE.md
- docs/STATUS.md
- 与本任务相关的功能、决策和运维文档

目标：
<用户或业务结果>

范围：
- <允许修改的模块或行为>
- <明确不做的事项>

验收条件：
1. <可观察结果>
2. <权限或状态约束>
3. <失败路径>

验证：
- <需要运行的自动化检查>
- <需要检查的桌面/移动页面>
- <不能使用生产数据进行的破坏性测试>

交付：
- 更新相关项目文档
- 汇总修改文件和行为
- 报告测试结果
- 说明部署、迁移和回滚影响
- 列出剩余风险
```

## 运维任务附加规则

默认只读。写明检查时间、证据来源、准确服务/数据库目标和发现。需要改代码时创建独立 hotfix；需要删除服务、恢复数据库、部署或修改环境变量时必须获得该动作的明确授权。

## 总控任务附加规则

总控任务不直接开发。它负责从 `main` 和项目文档读取当前状态、拆分任务、识别依赖、审核合并结果并更新 `docs/STATUS.md`。

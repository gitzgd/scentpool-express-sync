# 发货列表分页与完整批处理边界

## 目标

发货后台和门店看板只加载当前 50 单，避免订单增长后一次读取、传输和渲染全部收件信息与商品明细。分页只改变列表读取方式，不改变订单状态、权限或批处理范围。

## API

`GET /api/shipments` 支持：

- `page`：从 1 开始的正整数，默认 1；超过末页时返回最后一页。
- `page_size`：正整数，默认和硬上限均为 50。
- 原有门店、状态、日期、搜索和单条 ID 筛选保持不变。

响应包含当前页 `shipments`、状态枚举和 `pagination`：当前页、每页数量、匹配总数、总页数。非法参数返回 `400` 和可直接给操作员阅读的中文原因。

## 权限与数据安全

- 门店限制继续由数据库筛选生成器加入查询，不依赖前端隐藏。
- 列表仍不返回下单原始报文、签名盐或轮询令牌；只有带 ID 的单条物流详情请求可以读取物流原始轨迹。
- 没有 Schema 迁移，不更新任何订单、商品、面单或物流字段。

## 批处理边界

- CSV/XLSX 导出使用完整筛选查询，必须包含全部匹配订单。
- 电子面单批次预览和创建继续使用完整筛选查询，不受当前页面限制。
- PDF 合并打印从页面勾选订单，因此明确为“当前页待打印”和“全选本页”；操作员可逐页分批打印，每次仍受 50 单硬上限保护。

## 前端加载

- 初次进入后台时读取当前页及商品、门店、面单设置、活动批次和异常提醒。
- 切页只读取新的订单页；筛选会重置到第一页并刷新筛选汇总。
- 异常提醒保持独立 60 秒轮询，切页不会主动重复加载。

## 验收

- 两页数据、末页、越界回退、非法页码和每页上限。
- 总部全量与门店隔离后的分页总数。
- 导出和电子面单预览不被 50 单截断。
- 1440 px 与 390 px 下长业务 ID、长地址、长备注和多商品布局。

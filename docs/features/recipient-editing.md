# 待处理订单收件信息编辑

总部发货后台和门店/合作团队发货看板在收件信息下提供“编辑收件信息”，可修改收件姓名、联系电话和地址。总部可编辑全部归属，门店/团队只能编辑本单位；普通、售后和合作订单使用相同规则。

## 安全边界

- 必须处于“待处理”，且尚未进入取号流程：没有快递单号、取号请求号、供应商任务/订单标识或面单链接，也不处于排队/提交/已出单状态。
- 下单失败但仍保存取号请求号，不代表供应商一定没有面单，不能直接更换收件信息。须先由总部核实；有面单的订单仅在原取消流程确认供应商取消成功并清理原请求身份后才能修改。此功能不提供强行解锁或自动取消。
- `PATCH /api/shipments/{id}/recipient` 仅接受 `recipient_name`、`phone`、`address` 和整数 `content_revision`；姓名/电话/地址长度上限分别为 100/80/1000，电话沿用建单验证，拒绝空值、非法类型、控制字符和额外业务字段。
- `BEGIN IMMEDIATE` 内复核归属、状态及内容版本，与创建面单批次串行。旧表单不能覆盖更新；重复提交相同当前内容不重复改写。复用现有内容版本触发器，无 Schema/环境变量变更。
- 修改收件信息使旧打单预览指纹失效，总部必须重新核对，不能继续使用旧预览取号。不改订单编号、归属、商品、包装备注或原关联。

## 交互与失败

- 弹窗预填已有信息，保存时禁重复点击；保存成功只更新该单收件区，保留筛选、页码、滚动及行内其他未保存草稿。
- 后台轮询不覆盖弹窗输入。保存遇到冲突/失联时保留输入并显示文字原因；“重新读取当前信息”由员工主动点击，用最新值替换草稿以核对结果，不自动盲重试。
- 切换页面/退出登录时关闭弹窗，迟到响应不更新新身份页面。支持键盘焦点循环和 Escape，保存期间不能误关；移动端按钮换行。

## 验证与发布

- `python3 recipient_edit_test.py`：总部/门店/团队权限、API 鉴权、无效字段、并发版本冲突、重复提交、旧预览失效、排队/未知失败/已出单锁定和确认取消后编辑。加入完整 `smoke_test.py`；供应商响应均为合成，不执行真实取号。
- `node frontend_reliability_test.js`：入口状态与字段转义，保留既有生命周期、选择及防重复回归。
- 本地三个案例：`python3 recipient_edit_demo.py --port 8883`，打开 `http://127.0.0.1:8883/demo`。仅回环监听、临时合成库、封锁真实快递调用；正式服务器没有 `/demo` 路由。
- 发布前在线备份并校验完整性，发布后只读检查版本、资源、权限及业务聚合。回滚代码无需还原数据库；已由员工合法保存的新信息应保留，禁止恢复旧备份覆盖新订单。

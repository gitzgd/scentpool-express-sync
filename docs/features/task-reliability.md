# 任务可靠性与失败提示

## 目标

总部操作员不需要理解日志或代码，也能判断电子面单、物流查询和打印任务是否成功；遇到短暂外部故障时由系统安全恢复，不能恢复时明确显示原因和下一步操作，避免静默失败或重复提交。

## 适用任务

- 电子面单批量下单。
- 发货物流与退货物流查询。
- 批量面单 PDF 下载、合并与响应。

## 状态与恢复

- 电子面单限流、快递100服务端错误、超时或临时网络错误会使用原 `booking_request_id` 重试，保持请求幂等。默认额外重试 2 次，可用 `SCENTPOOL_SHIPPING_TRANSIENT_RETRIES` 在 `0` 至 `3` 之间调整。
- 快递100返回 `30011` 且同时提供完整快递单号和任务号时，按“重新取得面单成功”处理，即使供应商响应中的 `success` 字段为假也不再误报失败。
- 后台工作线程启动时和运行期间每分钟检查中断任务。处于“提交中”超过 10 分钟且累计尝试少于 3 次的任务会重新排队，并记录面向操作员的恢复说明。
- 累计尝试达到 3 次仍中断的任务会停止自动重试，批次项和订单都标为失败。只有操作员确认原因后，才通过页面按钮重新提交该批次中的失败项。
- 普通业务错误，例如网点、余额、授权或字段配置问题，不作为短暂网络故障自动重试，以免持续产生无效请求。

## 页面与接口

- 总部发货后台顶部固定显示“任务状态”。正常时明确显示“运行正常”；有问题时列出业务编号、门店、失败原因、处理建议和定位入口。地址行政区解析、承运区域停发/超区、网点余额/授权和临时网络故障会显示不同的处理建议。
- 面单失败可从告警卡片重新提交原批次的失败项；退货告警跳转到退货看板，其余告警定位到发货订单列表。
- 批量下单、物流同步和批量打印按钮在请求期间进入忙碌状态，防止重复点击。处理较慢时页面保留进度文字。
- 错误提示使用红色、可关闭的长时提示，并通过 `role="alert"` 和 `aria-live="assertive"` 通知辅助技术。后台状态读取失败也会持续显示，而不是被当作“没有失败”。
- `GET /api/admin/task-alerts` 仅限总部账号，返回任务类型、业务编号、门店、状态、错误摘要和更新时间；不返回收件人姓名、电话或地址。

## 打印安全

批量打印只有在 PDF 成功生成并开始返回给浏览器后才标记“打印成功”。下载或合并失败时保留待打印状态，页面明确提示减小选择数量后重试，避免任务失败但状态已被错误更新。

## 验收

- 烟测覆盖任务告警权限、隐私字段排除、短暂网络错误分类、中断任务重新排队和达到上限后失败。
- 前端语法检查通过，并在约 1440 px 桌面和 390 px 手机宽度检查长业务编号、长姓名、长地址、长备注及多商品订单。
- 生产部署后只读核对健康检查、总部任务状态和 Render 错误日志；不通过部署流程直接修改订单或生产数据库。

## 部署与回滚

本功能不修改数据库结构，不需要数据迁移。部署会增加一个只读总部接口和后台中断任务检查；回滚代码即可恢复旧行为。`SCENTPOOL_SHIPPING_TRANSIENT_RETRIES=0` 可临时关闭请求内自动重试，但不会关闭明确失败提示。

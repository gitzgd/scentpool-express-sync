# 任务可靠性与失败提示

## 目标

总部操作员不需要理解日志或代码，也能判断电子面单、物流查询和打印任务是否成功；遇到短暂外部故障时由系统安全恢复，不能恢复时明确显示原因和下一步操作，避免静默失败或重复提交。

## 适用任务

- 电子面单批量下单。
- 发货物流与退货物流查询。
- 批量面单 PDF 下载、合并与响应。

## 状态与恢复

- 电子面单限流、快递100服务端错误、超时或临时网络错误会使用原 `booking_request_id` 重试，保持请求幂等。默认额外重试 2 次，可用 `SCENTPOOL_SHIPPING_TRANSIENT_RETRIES` 在 `0` 至 `3` 之间调整。
- 快递100返回 `30011` 且同时提供完整快递单号和任务号时，按“重新取得面单成功”处理，即使供应商响应中的 `success` 字段为假也不再误报失败。
- 后台工作线程启动时和运行期间每分钟检查中断任务。处于“提交中”超过 10 分钟且累计尝试少于 3 次的任务会重新排队，并记录面向操作员的恢复说明。
- 累计尝试达到 3 次仍中断的任务会停止自动重试，批次项和订单都标为失败。只有操作员确认原因后，才通过页面按钮重新提交该批次中的失败项。
- 普通业务错误，例如网点、余额、授权或字段配置问题，不作为短暂网络故障自动重试，以免持续产生无效请求。
- 快递100实时查询遇到 HTTP `401/403/408/429/5xx`、连接失败或无效响应时，按“物流服务异常”处理：本轮只探测一个单号后立即停止，不把同一个平台故障写成几十条订单失败，也不覆盖订单已有物流状态。下一轮自动同步先再次探测，供应商恢复后才继续逐单查询。
- 快递100正常返回“查询无结果”或没有轨迹时仍属于“等待揽收”，不计为平台故障，也不显示为订单异常。

## 页面与接口

- 总部发货后台顶部使用“异常提醒”角标，不再默认展开整版失败卡片。点击后通过弹窗查看当前异常，关闭弹窗不会影响订单列表或正在填写的快递信息。
- 异常按“电子面单、物流查询、打印”分类，并进一步标记联系方式格式、停发或超范围、地址信息、授权或余额、暂未查到物流等原因；同时说明系统是否会继续自动检查。
- 同一次快递100平台故障合并为一张蓝色系统提醒，并显示受影响数量；该提醒没有“逐单人工处理”按钮，避免操作员误以为每个单号都要修改。历史平台失败只有在对应单号重新查询成功后才退出受影响数量，不执行批量状态重置。
- 每个分类都有独立的最多 100 项返回列表；即使最近 50 项全部是物流问题，“电子面单”分类仍能显示自己的异常，不再出现角标有数量但分类内容为空。
- 弹窗每 60 秒只刷新异常接口，不重新渲染订单表。底层发货物流默认每 6 小时、退货物流默认每 12 小时查询；生产环境变量可以调整这两个周期。
- 当前状态恢复后，异常会在下一次 60 秒刷新时自动消失。操作员也可以点击“标记人工已处理”隐藏当前这一次异常；该动作不修改订单、快递单号、电子面单或物流状态，同一问题产生新版本后会再次提醒。
- 地址行政区解析、承运区域停发/超区、网点余额/授权和临时网络故障会显示不同的处理建议。面单失败仍可从弹窗重新提交原批次的失败项；退货异常跳转到退货看板，其余异常定位到发货订单列表。
- 批量下单、物流同步和批量打印按钮在请求期间进入忙碌状态，防止重复点击。处理较慢时页面保留进度文字。
- 错误提示使用红色、可关闭的长时提示，并通过 `role="alert"` 和 `aria-live="assertive"` 通知辅助技术。后台状态读取失败也会持续显示，而不是被当作“没有失败”。
- `GET /api/admin/task-alerts` 仅限总部账号，返回任务类型、分类、业务编号、门店、状态、错误摘要、异常版本、系统影响数量和更新时间；`category_items` 提供每类独立列表。接口不返回收件人姓名、电话或地址。
- `POST /api/admin/task-alerts/resolve` 仅限总部账号，并同时校验异常标识和 64 位版本指纹。过期版本返回 `409`，防止把刚发生的新失败误当成已经处理。

## 人工处理记录

- `task_alert_acknowledgements` 只保存异常标识、类型、业务记录 ID、版本指纹、确认人用户 ID 和确认时间，不保存收件人、电话、地址、订单号、快递单号或第三方原始报文。
- `operational_incidents` 只保存系统异常标识、分类、面向操作员的摘要、影响数量和发生/恢复时间，不保存业务编号、快递单号、个人信息、密钥或第三方原始报文。
- `audit_state_events` 为脱敏日报只追加规范化状态和失败分类，可保留“当日失败后恢复”的统计证据；它不替代操作员异常弹窗，也不保存异常原文、业务编号、快递单号或个人信息。
- 每种异常使用独立标识，例如同一发货单的面单失败、物流失败和打印失败互不覆盖。
- 人工确认记录只抑制指纹完全相同的当前异常。失败原因或对应更新时间变化后会生成新指纹并再次展示，因此不能永久屏蔽未来故障。

## 打印安全

批量打印只有在 PDF 成功生成并开始返回给浏览器后才标记“打印成功”。下载或合并失败时保留待打印状态，页面明确提示减小选择数量后重试，避免任务失败但状态已被错误更新。

## 验收

- 烟测覆盖任务告警权限、隐私字段排除、异常分类、人工确认、过期指纹拒绝、同一问题再次发生重新提醒、真实恢复后自动清除、短暂网络错误分类、中断任务重新排队和达到上限后失败，以及 HTTP 403 系统分级、批次只探测一次、订单状态不被覆盖、平台故障聚合和分类列表防饥饿。
- 前端语法检查通过，并在约 1440 px 桌面和 390 px 手机宽度检查长业务编号、长姓名、长地址、长备注及多商品订单。
- 生产部署后只读核对健康检查、总部任务状态和 Render 错误日志；不通过部署流程直接修改订单或生产数据库。

## 部署与回滚

部署会以 `CREATE TABLE IF NOT EXISTS` 增量创建 `task_alert_acknowledgements` 和 `operational_incidents`，不批量改写现有订单、物流或面单数据。回滚代码可恢复旧界面；新增表可以安全保留，避免回滚时执行破坏性删表。`SCENTPOOL_SHIPPING_TRANSIENT_RETRIES=0` 可临时关闭电子面单请求内自动重试，但不会关闭明确失败提示。

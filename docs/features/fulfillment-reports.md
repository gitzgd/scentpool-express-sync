# 双渠道发货统计

## 业务口径

入口 `/reports/fulfillment`，总部看全部；门店及合作团队仅看自身。订单归属与实际发货渠道独立，渠道稳定标识为 `all / banna / kunming`。首版只统计系统登记发货量，不确认实际出库、不扣库存、不计算库存余额，退货不自动抵减。

只计当前 `已发货/已签收`、`已出单` 且有单号的有效记录。当前 `booking_request_id` 必须匹配成功批次明细；其私有配置快照中的 `profile_id` 必须唯一且有效。重复成功证据不重复计数；来源缺失或冲突不猜测渠道。当前面单等待揽收仍计入并单独提示。

- 供应商取消失败、未明确成功或本地未提交：不提前扣减。
- 供应商确认取消且数据库保存成功：当前有效记录退出统计，原日期/渠道/归属随之减少。
- 再次出单成功：新登记日期、新渠道、当前商品明细计入一次；出单失败不计。
- 复打不新增数量；签收保留原发货日期；旧物流版本和旧打印任务仍由原业务流程拒绝或忽略。
- 时间按北京时间，起止日期均包含，本周从周一开始。缺失或倒序时间排除并提示；估算时间保留标记。无日期记录提示为跨日期范围质量项，不能宣称属于所选日。所有历史数据原样保留。

## 页面与筛选

默认今日、全部渠道、权限范围内全部门店。支持昨日、本周、本月、上个月、自定义、门店/团队、具体发货类型、商品名称或条码。商品搜索只累计匹配的明细，订单数为这些明细涉及的去重订单数，不是整单所有商品数量。

三个视图共用筛选：每日渠道概览（含零日期）、门店商品汇总、每日商品明细。正式商品按条码、临时物料按名称及规格独立聚合；名称使用所选期间最近订单快照，同条码存在历史名称变化时提示，不依赖当前商品目录。数量沿用录入单位，不拆礼盒/套装。商品表最多每页 50 行，卡片合计涵盖全部匹配结果。

可见页每 15 秒读取一次本系统数据库；隐藏暂停，恢复可见/联网立即刷新。当前浏览器完成订单修改、取消或发现批次进度变化后发出无业务数据的同源刷新信号。单请求在途、排队最新条件、旧筛选响应丢弃；刷新失败保留旧值并明确提示，未成功加载不显示假零。保留筛选及滚动位置。不高频请求快递平台，不承诺发现尚未同步的外部取消。

## 接口与保护

- `GET /api/reports/fulfillment-items`
- `GET /api/reports/fulfillment-items.xlsx`
- 参数：`date_from/date_to/channel/store_id/shipment_type/q/view/page/page_size`；视图 `summary/daily_products`。最大日期跨度 3660 天；单页上限 50；商品搜索最多 100 字。
- 使用现有登录会话，审计令牌不可替代。服务端强制归属，门店显式请求其他归属返回 403。
- SQLite `mode=ro`、`query_only` 与只读事务，数据库聚合，不返回订单行、客户信息、内部用途、面单链接或配置快照。
- 同时最多 2 个看板查询；10 秒查询预算，忙/超时返回可读 503。新增批次请求组合索引及商品明细归属索引，不改任何业务列。
- 导出复用全站单导出锁、2 GiB 源库限制、128 MiB 输出限制、180 秒预算和磁盘空间预检。在线备份到私有临时快照，关闭生产读连接后生成四个工作表；文本标识明确以文本存储，数量为数值；临时文件权限 0600、请求完成后清理。
- 四表为每日渠道概览、门店商品汇总、每日商品明细、统计说明。导出忽略页码、保留其他筛选；同一快照合计一致，下载文件不会追随取消自动更新。

## 验收

`fulfillment_reports_test.py` 覆盖两渠道、归属、分类、分页、跨日月、商品快照、冲突/无日期、取消失败与成功、重发失败与成功、迟到物流/打印、重复证据、只读快照、导出隐私及索引幂等；已接入 `smoke_test.py`。`frontend_reports_test.js` 验证日期、乱序响应、单请求、错误保留、隐藏恢复和身份清理。`fulfillment_reports_load_test.py` 是可选 12,001 单合成负载检查。

`python3 fulfillment_reports_demo.py --port 8879` 启动仅回环访问的 `/demo`：同店双渠道、昆明昨日取消后今日版纳重发、多归属及临时物料混合。所有数据为合成临时库；禁用真实快递调用；演示路由只在该脚本内，不进入正式服务器。

## 发布与回滚

无新环境变量、密钥、第三方依赖或业务状态迁移。初始化仅创建两个可兼容索引；发布前仍须在线备份并验证完整性，发布后只读检查业务数量、权限和汇总。回滚代码即可，索引可保留；不可用部署前旧库覆盖上线后真实订单。现有历史渠道/时间证据缺失不会在本功能中被修复。

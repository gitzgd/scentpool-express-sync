## 可复现本地联调

使用项目 Python 环境运行：

```sh
python3 inventory_integration_demo.py --port 8891
```

只监听 `127.0.0.1`，自动创建 0700 临时目录和独立合成数据库；
启动输出只包含地址和 manifest 路径。随机本地令牌存于 manifest 指向的
0600 文件，客户端读入内存，禁止打印或提交。进程退出会删除临时库和令牌。
没有传入任意数据库路径的选项。外部连接、DNS 和子进程被封锁。

- 地址随启动端口变化；当前消费者验收使用新版 `http://127.0.0.1:8892/api/inventory/v1`。
  8891 是上一轮旧进程，不支持最终检查点协议，不应再用于最终验收。
- 主档商品 `DEMO-PRODUCT`；预置三条普通发货样本分别走版纳、昆明中通、昆明顺丰，
  第一条明确标为历史参考。manifest 提供样本 ID、创建 JSON 路径。
- 每次创建使用新 UUID reference；取号使用新 UUID request_key 与目录中的实际 revision。
- book 使用真实本地数据库队列；仅本地模拟 Worker 约 250 ms 处理一次并返回合成单号。
- PDF 是本机生成的空白合成文件，不下载、不打印任何真实面单。
- 另开放本地登录和总部单任务页；不开放生产运维入口。manifest 的 inventory_task_samples
  依次为可模拟取消、模拟拒绝取消、已取消三例，含长地址/名称和12条商品。
- 登录使用合成测试种子账号；不得使用生产凭据。取消请求使用固定合成响应，
  外部网络封锁仍生效；不得将模拟成功视为供应商验收。

启动后另一个终端运行：

```sh
python3 inventory_integration_http_check.py /绝对路径/manifest.json
```

## 重试、取消和恢复规则

- 人工明确重试失败取号：同 request_key、同原 profile_id/revision 重新排队原批次。
  排队/运行/成功状态重复POST只重放结果；GET永不重试，不应自动轮询POST。
- 确认供应商取消且保存成功后：新 key 使用新请求身份；旧key只能重放原批次身份。
  不新增库存客户端取消API；总部按ID核对并通过原权限/原供应商确认流程取消。
- 每页（包括空页）始终返回 stream_id、next_cursor、next_checkpoint；正游标续读必须
  携带上页 stream_id/checkpoint。只有next_cursor=0时checkpoint为空。
  校验失败409时停止并人工对账，不自动归零扣库存。
- `GET /dispatches/{id}` 返回 tracking_status；消费端保留并显示此值，不能以泛化的发货状态覆盖物流状态。
- 每页100单，每单最多500明细和262144明细字符，本页状态4 MiB；目录最多1000归属/
  20000商品/100万商品字符。查询10秒预算、接口最多2个并发；超限不返回截断状态。
- 普通列表、商品统计与普通异常中心不混入库存任务；库存失败由新中台GET明确呈现。
  API层允许总部按单笔ID核对并调用已有取消流程；门店/团队无权查看或修改。
  总部操作入口见下节，不扩展库存令牌权限。

### 总部单任务操作入口（2026-10-14 本地验证，未发布）

追加授权后新增 `/?inventory_task=<remote_id>`，由新中台生成指定任务深链接，不要求员工猜ID。
匿名只显示登录壳；使用原快递系统总部会话，门店403。单任务读取接口为
`GET /api/admin/inventory-tasks/{id}`，仅集成任务，普通订单404，库存/日报令牌401。
页面展示收件信息、明细、单号和状态供人工核对；不返回私有配置或原始报文。

人工确认后复用 `POST /api/shipments/{id}/label/cancel`，库存任务必须附读取时的
`expected_cancel_version`。旧页面版本不匹配409且不调用供应商；普通订单流程不变。
供应商拒绝/超时保留原面单，页面明确提示并禁重试，需主动刷新；会话过期隐藏收件信息。
成功后只提示回新中台刷新，确认 `booking_status=已取消` 且无单号后才允许新key换单，
仍沿用同一远端任务ID/source_ref，不自动取消、重发或记库存。

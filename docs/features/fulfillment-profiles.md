# 发货方案：昆明中通、昆明顺丰与版纳圆通

## 目标与使用流程

发货地点和订单所属门店是两个概念。门店、售后、合作账号和数据权限保持不变；总部在“批量打单”预览中选择本批次的发货方案。

- `kunming`：昆明中台／中通；`kunming_sf`：昆明中台／顺丰速运；`banna`：版纳门店／圆通。联系人、地址、菜鸟授权网点和模板分别保存。顺丰速运使用 `shunfeng`，不是顺丰快运。
- 每次打开“批量打单”均不选方案，必须人工选择；后端不使用旧默认值、原总部配置或订单已有快递字段兜底。真实联系方式、地址、网点及授权只存在生产设置，不放入公开仓库。
- 顺丰共用原菜鸟授权，产品类型初始“顺丰标快”（可编辑），不需要顺丰直连密钥。可先保存地址/授权网点，稍后填模板；缺基础模板时预览明确提示并禁止新下单，自定义区选填。不会复制中通/圆通模板。页面仅预填昆明方案已有地址，仍须确认保存。
- 顺丰、中通均在统计中归入昆明渠道；按有效批次的固定 `profile_id` 映射，不根据快递公司或当前设置猜测，未知/冲突快照继续待核实。
- 顺丰方案提供可选月结账号（非密钥），按结算约定填写，通过 `code` 传递并锁入原批次快照；不覆盖菜鸟 `partnerId/partnerKey`，不继承其他承运商全局 `code`。[快递100第三方平台说明](https://api.kuaidi100.com/document/disanfangdianshangpingtaimiwendingdan)列有顺丰月结账号映射；此处普通明文订单不新增平台订单导入流程。真实账号不进入测试/文档。
- 生产授权实测（2026-10-10）仅返回一个 `SF` 入口、无网点编号、数量 `0`。仅此顺丰直营返回形态改为“额度需由顺丰确认”的警告而非“余额耗尽”；并不承诺无限额度或供应商接单。其他网点保留零余额阻断，顺丰模板保护不放宽。
- 选择发生在取号前，不是下载 PDF 时。切换方案清空旧勾选；再次确认显示发货地、公司、网点和地址。
- 一批统一一个方案。已生成面单的下载、复打和物流保持原公司；打印单次 50 单上限、隔离合并流程不变。首版方案固定为 PDF／本地打印。
- 可以随时编辑地址，但只影响新提交批次；不会自动从菜鸟地址簿覆盖本系统设置。网点承接范围仍需业务核实。

## 边界与状态

- 保留原快递100 → 菜鸟授权渠道，新增中通 `zhongtong`，不切换到中通直连账号模式。共享现有菜鸟账号，不另建账号或保存新密码。
- 后端校验总部权限、固定方案与公司配对、当前授权网点、已知余额、配置版本和订单预览指纹；前端选择不是唯一防线。
- 预览指纹覆盖订单及发货配置。预览后地址、授权或余额变化，必须重新确认。
- 创建批次的同一事务为每项保存私有配置快照，包括寄件信息、网点、模板和授权。工作线程只用该快照；地址及默认值修改不会改变排队、短暂故障重试和原批次人工重试。
- 已尝试下单的记录不得用同一取号请求号换公司、地址或网点。历史失败项缺少快照时拒绝重试，需先人工核实供应商结果，不得仅清空本地编号重新取号。
- 此类历史待核对记录在预览中明确列为“不可下单”及原因；全选只提交可下单范围，避免一条旧失败单阻塞所有新订单。不会自动隐藏异常或更改旧单状态。
- 取消继续使用原下单授权快照。只有供应商确认成功才清空面单；重新下单使用新请求号。
- 菜鸟账号变化后要求重新核对方案；同账号凭证刷新不影响已保存方案，但旧批次仍使用其原凭证，失效时应明确报错，不能悄悄换授权。

## 数据和接口

- 增量表 `fulfillment_profiles`，版本化配置；保留 `shipping_settings.default_profile_id` 列以兼容旧 Schema，但初始化清空，不再允许设为默认。升级只清空这个配置字段，不重写批次快照。
- `shipping_batch_items.settings_snapshot_json` 为私有持久快照，不出现在普通订单、批次 API 或日报。
- `shipping_batches.fulfillment_name`、`shipments.fulfillment_name` 保存实际使用的方案名称，供总部识别；旧单为空，不能倒填。
- 总部 `PUT /api/admin/fulfillment-profiles` 保存一个方案；原设置接口返回白名单方案信息，授权继续脱敏。
- 预览可省略 `profile_id`，仅返回待选择提示及订单范围，`settings_ready=false`；创建批次必须有显式有效方案和匹配预览指纹。省略、空串或旧前端携带默认请求均不能静默下单。
- 迁移不改历史订单数量、状态、时间、单号或门店。无新增环境变量。

## 验证

`fulfillment_profiles_test.py` 使用合成数据库和供应商响应，覆盖权限、网点、版本冲突、零余额、预览失效、跨页全选、配置快照、凭证刷新、原批次重试、孤立请求号、历史任务保护、原授权取消和重复迁移。专项纳入完整 `smoke_test.py`。

本地合成界面：`python3 fulfillment_demo.py --port 8880`，访问 `http://127.0.0.1:8880/demo`。仅回环监听、临时数据库、封锁对外快递请求，不启动真实下单/打印；手动选择、顺丰模板未配置、三方案切换与配置锁定三个案例不进入生产数据库。生产服务器没有 `/demo` 路由。

## 上线与回滚

1. 核对正确 Render 服务、当前版本、业务数量和面单活动队列；先做在线备份并校验完整性和权限。
2. 发布增量 Schema 和代码，复核健康、权限、业务数量。迁移不创建或启用任何方案。
3. 刷新原菜鸟账号网点，必须看到实际返回的目标承运商网点。新增顺丰复用已保存昆明地址，模板留空由用户填写，原中通/圆通配置不变。多个顺丰网点时须人工确认，不猜测 `tbNet`。所有新批次均手动选择。
4. 未完成旧版排队任务缺少快照时，阻止配置、授权和网点变更，先等待其结束。
5. 仅执行预览和聚合验收；正式取号会消耗面单额度，首次实单必须确认具体订单。默认中通模板的纸张和商品区、网点上门承接范围、实际本地打印效果不能用模拟测试代替。
6. 首选向前修复；有新方案排队任务时不可直接回退旧工作线程（它不认识快照）。停止新提交并排空/核实队列后，才评估代码回退。恢复备份可能丢失备份后订单，必须独立授权；不得以回滚为由重置业务数据。

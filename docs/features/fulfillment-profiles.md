# 发货方案：中台中通与版纳圆通

## 目标与使用流程

发货地点和订单所属门店是两个概念。门店、售后、合作账号和数据权限保持不变；总部在“批量打单”预览中选择本批次的发货方案。

- `kunming`：昆明中台／中通；`banna`：版纳门店／圆通。联系人、地址、菜鸟授权网点和模板分别保存。
- “面单设置”先保存原版纳配置，再配置中台并设为默认。真实联系方式、地址、网点及授权只存在生产设置，不放入公开仓库。
- 选择发生在取号前，不是下载 PDF 时。切换方案清空旧勾选；再次确认显示发货地、公司、网点和地址。
- 一批统一一个方案。已生成面单的下载、复打和物流保持原公司；打印单次 50 单上限、隔离合并流程不变。首版方案固定为 PDF／本地打印。
- 可以随时编辑地址，但只影响新提交批次；不会自动从菜鸟地址簿覆盖本系统设置。网点承接范围仍需业务核实。

## 边界与状态

- 保留原快递100 → 菜鸟授权渠道，新增中通 `zhongtong`，不切换到中通直连账号模式。共享现有菜鸟账号，不另建账号或保存新密码。
- 后端校验总部权限、固定方案与公司配对、当前授权网点、已知余额、配置版本和订单预览指纹；前端选择不是唯一防线。
- 预览指纹覆盖订单及发货配置。预览后地址、默认值、授权或余额变化，必须重新确认。
- 创建批次的同一事务为每项保存私有配置快照，包括寄件信息、网点、模板和授权。工作线程只用该快照；地址及默认值修改不会改变排队、短暂故障重试和原批次人工重试。
- 已尝试下单的记录不得用同一取号请求号换公司、地址或网点。历史失败项缺少快照时拒绝重试，需先人工核实供应商结果，不得仅清空本地编号重新取号。
- 取消继续使用原下单授权快照。只有供应商确认成功才清空面单；重新下单使用新请求号。
- 菜鸟账号变化后要求重新核对方案；同账号凭证刷新不影响已保存方案，但旧批次仍使用其原凭证，失效时应明确报错，不能悄悄换授权。

## 数据和接口

- 增量表 `fulfillment_profiles`，版本化配置；`shipping_settings.default_profile_id` 初始为空，不自动切换生产。
- `shipping_batch_items.settings_snapshot_json` 为私有持久快照，不出现在普通订单、批次 API 或日报。
- `shipping_batches.fulfillment_name`、`shipments.fulfillment_name` 保存实际使用的方案名称，供总部识别；旧单为空，不能倒填。
- 总部 `PUT /api/admin/fulfillment-profiles` 保存一个方案；原设置接口返回白名单方案信息，授权继续脱敏。
- 预览及创建批次接口新增可选 `profile_id`；省略使用默认，启用默认后不能用空串绕过。
- 迁移不改历史订单数量、状态、时间、单号或门店。无新增环境变量。

## 验证

`fulfillment_profiles_test.py` 使用合成数据库和供应商响应，覆盖权限、网点、版本冲突、零余额、预览失效、跨页全选、配置快照、凭证刷新、原批次重试、孤立请求号、历史任务保护、原授权取消和重复迁移。专项纳入完整 `smoke_test.py`。

本地合成界面：`python3 fulfillment_demo.py --port 8878`，访问 `http://127.0.0.1:8878/demo`。仅回环监听、临时数据库、封锁对外快递请求，不启动真实下单/打印；默认中台、切换版纳和配置锁定三个案例不进入生产数据库。生产服务器没有 `/demo` 路由。

## 上线与回滚

1. 核对正确 Render 服务、当前版本、业务数量和面单活动队列；先做在线备份并校验完整性和权限。
2. 发布增量 Schema 和代码，复核健康、权限、业务数量。迁移不创建或启用任何方案。
3. 刷新原菜鸟账号网点，必须看到实际返回的中通网点。保留原圆通地址/网点/模板为版纳方案，再保存中台方案并启用默认。不能推测网点 `tbNet`。
4. 未完成旧版排队任务缺少快照时，阻止配置、授权和网点变更，先等待其结束。
5. 仅执行预览和聚合验收；正式取号会消耗面单额度，首次实单必须确认具体订单。默认中通模板的纸张和商品区、网点上门承接范围、实际本地打印效果不能用模拟测试代替。
6. 首选向前修复；有新方案排队任务时不可直接回退旧工作线程（它不认识快照）。停止新提交并排空/核实队列后，才评估代码回退。恢复备份可能丢失备份后订单，必须独立授权；不得以回滚为由重置业务数据。
